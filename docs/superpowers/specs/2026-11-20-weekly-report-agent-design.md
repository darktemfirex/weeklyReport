# 주간보고 자동 작성 에이전트 설계

작성일: 2026-11-20 / 상태: 사용자 확인 대기

## 1. 의도와 이유
SM 담당자가 매주 한글(hwpx)로 작성하는 주간보고(유통운영1팀)를 자동화한다.
건별 사유/내용/개발일정/요청부서/완료(예정)일과 CSR 수치만 입력하면, 기존 보고서와
동일한 서식·폰트·문체의 hwpx 파일이 생성되어야 한다. 보고 전주에 작성하는 것이 원칙이다.

## 2. 목표 / 비목표 / 안티골
- 목표
  - `data/`의 최신 파일을 템플릿 겸 이력으로 사용해 다음 주 hwpx 생성
  - 일정 기반 이월 후보 제안과 (계속) 자동 판정
  - 웹 폼 입력 + 생성 전 미리보기
- 비목표: 보고서 제출/메일 발송, 여러 팀 지원, 한글 프로그램(HWP COM) 자동화
- 안티골: 폰트/서식이 달라지는 것, 날짜가 틀리는 것, 한글에서 열리지 않는 파일, LLM이 입력에 없는 사실을 지어내는 것

## 3. 입력 데이터 분석 (샘플 3개: 20261109 / 20261116 / 20261123)
- hwpx = zip. 본문은 `Contents/section0.xml`, 서식은 `Contents/header.xml`, 표 4개.
  - 표1: 부서명 / 금주 계획사항(기간) / 차주 계획사항(기간)
  - 표2: 금주 칸·차주 칸 각각 `7. 농/축/수산물 결함 및 개선사항` + 건별 문단들
  - 표3·4: CSR 처리현황(접수기간, 물류 요청/처리/처리율, 전화문의, 장애현황 발생/적기복구)
- 건 구조: 타이틀(○) / 사유 / 내용(또는 개발내용) / 개발일정(단계별) / 요청부서 / 완료(예정)일
  - 줄 종류별 문단 스타일(paraPr)이 고정, 한 줄 내에서도 기호·날짜별 글자 스타일(charPr)이 갈림
- 파일명 = 보고일(월요일). 최신 20261123 → 다음 파일은 `20261130.hwpx`

## 4. 날짜 규칙 (코드가 계산)
- 새 파일명 날짜 = 최신 파일 날짜 + 7일. 금주 = 그 주 월~금, 차주 = +7일, CSR 접수기간 = 금주 직전 주 월~금
- 예: 20261130 → 금주 11.30~12.04, 차주 12.07~12.11, 접수 11.23~11.27
- 날짜 표기는 샘플 형식 유지: `‘26.11.30.(월)`

## 5. (계속) 판정 (사용자 확정 규칙)
건의 **개발 단계 일정**(분석/설계, 개발/테스트 등. `본적용 및 모니터링`은 제외)이 해당 주(월~금)와 겹치고
그 단계의 시작일이 해당 주 월요일보다 앞서면 타이틀 뒤에 ` (계속)`. 금주·차주 칸 모두 동일 적용.
샘플 6개 타이틀(금주 3, 차주 3)이 전부 이 규칙과 일치함을 확인했다. 단위 테스트로 고정한다.

## 6. 이월 후보
직전 보고서를 건 단위로 파싱(타이틀/사유/내용/단계별 일정/요청부서/완료일)하고, 새 금주와
일정(본적용 포함)이 겹치는 건을 금주 칸 후보로 제안한다. 후보는 사용자가 체크/수정/제외하며,
실제 계획이 바뀔 수 있으므로 자동 확정하지 않는다(샘플에서도 0116 차주 건이 0123에 이월되지 않음).

## 7. 접근 방식 (선택 결과)
1. 템플릿 복제 + 문단 치환 (선택): 최신 hwpx를 복제하고 건 영역만 줄 유형별 견본 문단을 복제해 채움 → 서식 100% 유지
2. hwpx를 코드로 신규 생성: 서식 재현 위험이 커서 제외
3. LLM이 XML을 직접 작성: 깨질 위험이 커서 제외

입력 UI는 간단한 웹 폼(Streamlit) (사용자 선택). CLI는 제외.

## 8. 구성
```
Streamlit 폼 ──> LangGraph
  load_prev(hwpx 파싱) → calc_weeks(코드) → carry_candidates(코드) → [사용자 확인]
  → compose(LLM: 타이틀/사유/내용 문체 정리, 구조화 출력) → mark_continue(코드)
  → render_hwpx(코드, 템플릿 치환) → verify(하네스) → 실패 시 compose 재시도/오류 표시
```
- 폼 입력: 신규 건(사유/내용/개발일정 단계들/요청부서/완료(예정)일), 이월 후보 체크, CSR 숫자(요청/처리/전화문의/장애 발생/적기복구)
- LLM 역할은 문체 정리와 타이틀 생성뿐. 날짜/일정/(계속)/렌더링은 모두 결정적 코드. 입력에 없는 정보를 추가하지 않는다.
- LangChain은 모델 호출과 Pydantic 구조화 출력에만 얇게 사용.
- RAG: `data/` 과거 보고서를 건 단위로 색인, 유사 과거 건의 타이틀·문체를 few-shot으로 제공. 샘플이 적은 초기에는 전체 건 few-shot으로 대체 가능(구현 시 판단).
- CSR 표: `CSR처리현황 및 문의 응대 현황` 문구 고정, 접수기간과 숫자만 변경(처리율은 처리/요청으로 계산)

## 9. 하네스(검증)
- 단위: 주차 계산, (계속) 판정(샘플 6케이스), 일정 파싱
- 골든: 샘플 3개를 파싱 → 같은 입력으로 재생성 → 텍스트/서식 ID 비교
- 산출물 검증: zip/XML 유효성, `mimetype` 첫 항목·무압축 등 hwpx 규칙, 사용된 paraPr/charPr ID가 템플릿과 동일, 고정 문구 유지, 날짜 형식
- 가능하면 한글 뷰어에서 열림 확인은 사용자가 최종 수행(자동화 비목표)

## 10. 제약 / 위험
- 사내 문서이므로 외부 LLM 사용 가능 여부 미확인 → 모델은 설정으로 교체 가능하게 하고 LLM 호출부를 분리
- 한글 프로그램에서 열림은 자동 검증 불가 → 구조 보존 방식으로 위험 최소화
- 개발 환경: Windows, Python 3.12, lxml 미설치(필요 시 설치)

## 10-1. 검토에서 보완한 결정 (작성자의 판단, 변경 가능)
- 샘플 3개는 `data/`에 있고 분석 완료. 최신 파일의 금주/차주 칸에서 줄 유형별 견본 문단을 뽑고, 해당 유형이 없으면 이전 파일에서 찾는다.
- 건의 소속: 후보 풀 = 직전 보고서의 모든 건 + 폼에서 새로 입력한 건. 각 건은 일정이 새 금주/새 차주와 겹치는지로 금주/차주 칸에 자동 배정하고(둘 다 가능, 0109처럼), 사용자가 체크로 가감한다. 기존 칸의 내용은 모두 교체한다.
- 표1의 금주/차주 기간 문구는 날짜 계산 결과로 생성. 부서명(`유통운영1팀`)과 `7. 농/축/수산물 결함 및 개선사항` 제목은 그대로 복사. 건이 없는 칸은 제목만 남긴다.
- 개발일정 단계명은 자유 텍스트. 날짜는 단일/범위/종료일 없는 범위(`11.30 ~`) 허용. (계속) 판정에서는 `본적용` 포함 단계를 제외하고, 시작일이 없는 단계는 무시한다.
- 폼은 2단계(이월 후보 확인 → 신규 입력/CSR)로 나누고 LangGraph 체크포인트는 쓰지 않는다. 미리보기는 텍스트/HTML 요약이며 실제 hwpx 렌더링은 하지 않는다.
- "입력에 없는 사실" 방지: 출력의 숫자·날짜는 모두 입력 또는 계산 결과에 있어야 한다는 규칙 기반 검사를 두고, 실패 시 최대 2회 재시도 후 오류 표시.
- RAG는 1차에서 벡터 색인 없이 전체 과거 건 few-shot으로 시작하고, 검색 인터페이스만 분리해 둔다.
- CSR: 숫자는 정수, 처리율은 처리/요청의 정수 % (요청 0이면 `-`). 장애 문구 등 다른 가변 항목은 샘플에 없어 숫자 5개만 입력받는다.
- 주는 항상 월~금(공휴일 보정 없음). 연말 파일명도 같은 규칙.

## 10-2. 참고 구현 반영 (사용자 지시: 기술 부분은 `C:\1.devkjh\axedu\nh-agent-lab`의 에이전트를 따른다)
참고한 파일: `CLAUDE.md`, `requirements.txt`, `완성본/5교시/{agent,graph,guardrails,mcp_server,manual_search}.py`, `검증/run_cases.py`. (`.env`는 키가 들어 있어 읽지 않음)

위 10-1과 다르게 바뀌는 점은 이 절이 우선한다.
- **LLM**: `.env`의 `OPENAI_API_KEY / OPENAI_BASE_URL(AXRouter) / CHAT_MODEL / EMBED_MODEL`, `python-dotenv` + `langchain-openai`의 `ChatOpenAI(temperature=0)`·`OpenAIEmbeddings(check_embedding_ctx_length=False)`. 외부 LLM 사용 가능 여부 문제는 사내 게이트웨이 사용으로 해소. 키 값은 출력하지 않는다. `.env`는 이 프로젝트에 사용자가 직접 복사한다(키 파일이라 임의 복사하지 않음).
- **패키지**: 참고 프로젝트의 `requirements.txt` 버전 고정(langchain 1.5.2, langgraph 1.2.23, langchain-openai 1.8.3 등)을 그대로 쓰고, 이 프로젝트 전용 `.venv`를 만든다. 추가는 `streamlit`(웹 폼)뿐이며 버전 고정. hwpx 처리는 표준 라이브러리(zipfile, xml.etree)로 한다(lxml 불필요).
- **구성(파일 계층을 동일하게)**:
  - `manual_search.py` 대응 → `item_search.py`: 과거 보고서를 건 단위 Document로 나눠 `InMemoryVectorStore` + 임베딩 검색(RAG), 출처는 `파일명/칸/건 번호`. PydanticOutputParser로 구조화 출력.
  - `mcp_server.py` 대응 → `mcp_server.py` (FastMCP, stdio, print 금지): 도구 `read_report`(hwpx 파싱), `calc_weeks`, `search_items`(RAG), `render_hwpx`(저장). 권한 표: 읽기·계산·검색은 자동, `render_hwpx`는 사용자 승인 후.
  - `agent.py`: ReAct 루프 Agent 클래스(도구 바인딩, 반복 상한, on_event) 재사용. 직전 보고서 읽기 · 이월 후보 정리 담당.
  - `graph.py`: LangGraph `StateGraph` + `InMemorySaver` + `interrupt()`/`Command(resume=...)`로 "사용자 확인(이월 후보·최종 승인)" 구현. 폼 2단계는 이 interrupt에 대응(체크포인트 사용으로 10-1 결정 변경). 노드: 직전보고 읽기 → 주차 계산 → 이월 후보 → 사용자 확인 → 초안(LLM) → (계속) 표시 → 검증 → 사용자 승인 → hwpx 저장. 검증 실패는 최대 2회 재작성 후 사람 이관(반려 상한 `MAX_REJECT`와 같은 방식).
  - `guardrails.py`: `check(text)`/`mask(text)` 형태 유지. 규칙1: 출력의 숫자·날짜가 입력/계산 결과에 없으면 차단(입력에 없는 사실 금지). 규칙2: 주민·카드·전화번호 원문은 로그·산출물에 남기지 않고 가린다.
  - 실행 로그: `RunLog(AsyncCallbackHandler)`가 `logs/run-시각-보고일.jsonl`에 도구·LLM 호출·토큰·승인 결과를 기록(개인정보 가림).
  - `console.py` 대응 UI → `app.py`(Streamlit 폼): 입력/이월 후보 체크/미리보기/승인 버튼. 하네스 결과는 `reports/`에 `YYYYMMDD.hwpx`로 저장.
- **하네스(검증)**: `검증/cases.json` + `검증/run_cases.py` + `검증/비교표.md`를 그대로 따른다. 케이스 = 입력, 기대 동작(타이틀/(계속)/기간/CSR 값/끝 노드/저장 여부), 판정 함수 `judge`가 어긋난 점을 모아 표로 출력. 케이스: (계속) 6개 샘플, 이월 후보, 입력 없는 숫자 차단, 개인정보 가림, hwpx 구조 검증 실패 시 사람 이관.
- **코딩 규칙(참고 프로젝트 CLAUDE.md)**: 짧고 단순하게, 요청 안 한 기능 금지, UTF-8, `sys.stdout.reconfigure(encoding="utf-8")`, PowerShell 명령 기준 안내, 모델이 할 일(요약·타이틀)을 코드에 미리 적지 않는다.
